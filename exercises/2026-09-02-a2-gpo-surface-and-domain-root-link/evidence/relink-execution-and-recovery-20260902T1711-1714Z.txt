ROOT CAUSE of the Remove-GPLink failure: Remove-GPLink's -Target parameter does not accept the
DNS-form domain name ("district.local") that New-GPLink accepted for the same conceptual target,
and that GPOReport's own SOMPath field displays. It requires the distinguishedName form
("DC=district,DC=local") instead. This is an inconsistency in the GroupPolicy module's own cmdlets,
not a mistake in identifying the right target.

FINAL STATE, confirmed: Secure Admin WS linked only to OU=Workstations and
OU=Servers/OU=Application Servers. No domain-root link. No Deny-Apply ACE (removed, and now
unnecessary since nothing links the GPO to DC01's OU chain). DC01's gpresult shows Secure Admin WS
absent entirely.
