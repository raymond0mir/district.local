Context: 2026-09-05's evidence-log left two untested hypotheses for why `-installcert` hung
indefinitely under `qm guest exec` (session 0): that it raises a credential or confirmation
dialog that cannot render with no desktop, or that it retries/waits past a denial rather than
failing. `-dspublish` had already proven a plain rights denial returns in under a second, which
argued against rights alone explaining a hang.

Run at an interactive console this time, the command produced a modal dialog:

"Microsoft Active Directory Certificate Services -- Cannot verify certificate chain. Do you wish
to ignore the error and continue? The revocation function was unable to check revocation for the
certificate. 0x80092012 (-2146885614 CRYPT_E_NO_REVOCATION_CHECK)"

This is Recalled -- observed on screen through the noVNC console, not machine output. Clicking
OK let the command return within seconds. This resolves the 2026-09-05 question: the hang was
the dialog blocking with no desktop to render it in, not a rights-driven retry loop.

The dialog itself is a direct, expected consequence of the earlier decision to skip publishing a
CRL (evidence-log.md, "Where Raymond was consulted," item 1, 2026-09-05).

rather than trusted from the screen:
