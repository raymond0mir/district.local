--------------------------------------------------------------------------------
What this proves
--------------------------------------------------------------------------------

- The CA "district.local Issuing CA" grants Allow Enroll to NT AUTHORITY\Authenticated
  Users. jsmith's token carries S-1-5-11 Authenticated Users (evidence/34), so jsmith
  holds the CA-level enroll right.
- CA Administrator and Certificate Manager are held by BUILTIN\Administrators,
  DISTRICT\Domain Admins and DISTRICT\Enterprise Admins. No other principal appears.
- The enrollment wizard's first stated reason, "The permissions on this certification
  authority do not allow the current user to enroll for certificates", is not the cause.

--------------------------------------------------------------------------------
Recalled, not captured
--------------------------------------------------------------------------------

The enrollment wizard's own text, seen at CA01's console 2026-09-07 and reproduced with
its Details pane expanded:

  district.local Client Authentication -- STATUS: Unavailable
  "The permissions on this certification authority do not allow the current user to
   enroll for certificates. A valid certification authority (CA) configured to issue
   certificates based on this template cannot be located, or the CA does not support
   this operation, or the CA is not trusted."
  Key usage: Digital signature, Key encipherment
  Application policies: Client Authentication
  Validity period (days): 365

This is a screenshot and stays Recalled. The block lists candidate causes rather than a
diagnosis. The first candidate is disproven by the capture above.

--------------------------------------------------------------------------------
Name-form result, captured in passing
--------------------------------------------------------------------------------

certreq -enroll resolves the template cn, not the friendly name. Three runs using
"district.local Client Authentication" returned "Template not found" and 0x80094801
CERTSRV_E_NO_CERT_TYPE. A fourth run using the cn, district.localClientAuthentication,
34 characters, launched the Certificate Enrollment wizard instead. The name form was a
real artifact in this exercise's earlier attempts, and it is not the underlying failure:
the wizard it launched reports the template Unavailable.
